# Фудграм

**Проект в облаке:** http://ladygagahasachild.work.gd/  
**Спецификация API (Redoc):** http://ladygagahasachild.work.gd/api/docs/  
**Админ-зона:** http://ladygagahasachild.work.gd/admin/

## О проекте

«Фудграм» — сайт для публикации, поиска и сохранения рецептов. Пользователи могут делиться своими блюдами, подписываться на авторов и формировать список покупок.

### Возможности

- регистрация и авторизация пользователей;
- публикация, редактирование и удаление собственных рецептов;
- добавление изображений, ингредиентов и тегов к рецептам;
- фильтрация рецептов по тегам и автору;
- добавление рецептов в избранное;
- подписка на авторов;
- формирование списка покупок и скачивание его в формате `.txt`;
- короткие ссылки на рецепты;
- административная панель для управления пользователями, рецептами и ингредиентами.

## Структура проекта

- `backend/` — серверная часть на Django.
- `frontend/` — клиентская часть на React.
- `infra/` — конфигурация Nginx и локального Docker Compose.
- `data/` — данные для загрузки ингредиентов.
- `docker-compose.production.yml` — конфигурация production-развёртывания.
- `tests.yml` — данные для проверки проекта.

## Настройка переменных окружения

Перед запуском необходимо подготовить файл `.env` на основе шаблона проекта:

```bash
cp backend/.env.example backend/.env
```

Заполните переменные окружения в соответствии с шаблоном `.env.example`.

В production необходимо:
- установить `DEBUG=False`;
- задать уникальный секретный ключ Django;
- указать домен и IP сервера в `ALLOWED_HOSTS`;
- задать параметры подключения к PostgreSQL;
- задать надёжные пароли администратора и тестовых пользователей;
- настроить доверенные источники CSRF, если используется HTTPS.

Не публикуйте `.env` и не добавляйте его в Git.

## Локальный запуск

Для локального запуска используется отдельная конфигурация Docker Compose:

```bash
git clone https://github.com/alevtinamuz/foodgram.git
cd foodgram
```

Подготовьте переменные окружения согласно `backend/.env.example`, затем запустите:

```bash
cd infra
docker compose up --build
```

После запуска:
- сайт: http://localhost/
- API: http://localhost/api/
- документация API: http://localhost/api/docs/
- админ-зона: http://localhost/admin/

## Production-развёртывание

Production-конфигурация находится в корне проекта в файле `docker-compose.production.yml`.

### Подготовка сервера

1. Установите на сервер Docker и Docker Compose.
2. Подготовьте рабочую директорию проекта.
3. Получите исходный код проекта из GitHub.
4. Создайте production-файл `.env` с необходимыми переменными окружения.
5. Убедитесь, что домен направлен на IP-адрес сервера.

### Запуск production-контейнеров

Из корневой директории проекта выполните:

```bash
sudo docker compose -f docker-compose.production.yml pull
sudo docker compose -f docker-compose.production.yml up -d
```

Проверить состояние контейнеров:

```bash
sudo docker compose -f docker-compose.production.yml ps
```

Посмотреть логи backend:

```bash
sudo docker compose -f docker-compose.production.yml logs backend
```

### Автоматический деплой

Для автоматического развёртывания используется GitHub Actions.

В настройках репозитория GitHub в разделе **Settings → Secrets and variables → Actions** добавлены следующие Repository Secrets:

| Секрет | Назначение |
|---|---|
| `DOCKER_USERNAME` | Имя пользователя Docker Hub |
| `DOCKER_PASSWORD` | Пароль или токен Docker Hub |
| `HOST` | IP-адрес сервера |
| `USER` | Пользователь сервера для SSH-подключения |
| `SSH_KEY` | Приватный SSH-ключ для подключения к серверу |
| `TELEGRAM_TO` | Идентификатор получателя уведомлений Telegram |
| `TELEGRAM_TOKEN` | Токен Telegram-бота |

После отправки изменений в ветку `main` GitHub Actions запускает настроенный процесс проверки, сборки и публикации Docker-образов, а затем выполняет развёртывание на сервере.

## Загрузка ингредиентов и тестовых данных

Для загрузки ингредиентов используется management-команда:

```bash
python manage.py load_ingredients
```

Команда читает данные из JSON-файла `data/ingredients.json` и добавляет ингредиенты в базу данных. Уже существующие записи не дублируются.

Для создания тестовых пользователей и рецептов используется команда:

```bash
python manage.py load_test_data
```

Команда создаёт трёх тестовых пользователей и до девяти тестовых рецептов. Если заданы `ADMIN_EMAIL` и `ADMIN_PASSWORD`, также создаётся суперпользователь.

Повторный запуск не создаёт дубликаты уже существующих рецептов.

**Важно:** команда создаёт демонстрационные изображения-заглушки для тестовых рецептов.

В production запускайте команды осознанно: они изменяют содержимое базы данных. Не используйте команды очистки тестовой базы на рабочем сервере.
